calm dog down

2026-08-08

A fun, useful app built with Cline+Gemma4:31b for your dog.

Agent Setup

  • Cline + openai-compact:gemma4:31b housed on our server (vscode plugin)
  • I added a .clinerules directory at the top for what a commit message looks like and overall developer styling (casing, organization, etc.)
  • Then I added a memory-bank by asking cline to "Initialize a memory bank" - this looks at directory and generates a few files. These are overly wordy and duplicative so I asked it to consolidate them down to two (one for stakeholders/overview, one for tech, and one for developers - architecture diagrams in mermaid, testing, etc.)
  • Then I fired away commands with subagents, native tool calling, autocompact, checkpoints, and hooks enabled with 256k tokens max for context

What Failed

  • Perhaps the model version or server setup, but I got many 400 errors and failed tool calls (especially as context neared 256k)
  • It seemed to ignore many .clinerules - e.g. not test-driven development (only when I explicitly prompted it), not updating the memory bank / docs, etc.
  • It waits forever without timeouts set in place for scripts (.e.g. ./test.sh and the code has some infinite loop) - Cline then claims "it's thinking..." and never finishes
  • When it stalled, I sometimes had to close vscode and then resume - but resume didn't work OR /newtask was disabled / the button to execute was greyed out

What Worked

  • For the timeout errors, I simply exited the script (ctrl+c) and sometimess had to close my vscode and resume the task
  • Test-driven development - prompt it with a workflow in mind (e.g. report sent via SMTP) and make sure it adds a test; I find it does a great job with the right feedback/test suite
  • Then make sure it doesn't delete tests unless prompted; just like regular development, this helps prevent regression and Cline really works well with binary feedback from testing
  • Keep it simple and stupid / self-contained; it's a junior developer with limited context but you can ping it a zillion times without overworking them :)
  • Make sure versions are pinned; I don't care if it's a simple Python app, pin versions (or ask it to); its rate of hallucination drops significantly and your project is more likely to not be shelfware
  • Make sure you set line limits or make sure code organization is alright; if you have a massive HTML file that grows, that will not fit in context and grepping line by line will kill you (or your agent to be specific)

Next Steps

  • hooking this up with git worktrees (e.g. commits are tasks now)
  • adding a ci/cd pipeline to ground the agent
  • rethinking meta-level invariants / clinerules - I don't think text is enough for it to execute properly
  • Voice cloning w/ a free provider??

App Features

  • This app will be great - it calls Google TTS for voice samples, groq for sample phrases for Cooper, and then uses MAB/epsilon-greedy policy to discern the phrase and pitch to fire off should a bark / sound above a certain frequency arise
  • I LOVE that caching works now so every run is not a pain in the butt to set up and that reporting works and sends me something interesting via email so I know if my dog is annoying my neighbors
  • I'm upset about ElevenLabs and their predatory API pricing... capitalists ruining everything (oh wait I'm American too...)

  • Save off mp3s of XX seconds after each phrase fires to the email account (housed in drive for instance); up to some XX in megabytes or something
